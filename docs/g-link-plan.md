# ゴッドリンク（G・リンク）実装計画（2026-10-31 策定）

## 実装状況（2026-10-31、第16弾で実施）

Phase 0〜5 を実装した。検証は `tests/test_vocab_pilot16.py`（全サイクル＋離脱置換）と `tests/test_vocab_pilot16_cards.py`（代表カード parse）。

- 表現: Card.link（グループID）。代表は中央→一番左の順で決め、bz_tops は代表だけを返す（グループを1体として扱う）
- 特性統合: chars でグループ全員分を合算する（パワー・コストは合計、キーワード・種族・文明・タイプは和集合、許可・禁止は連結）。誘発は全員の能力が代表を発生源として誘発する
- リンク手順: ゴッドが出た直後に g_link タスクが割り込む。中央はリンク外し（1枚ずつ、繰り返し可）→リンク先の選択、左/右はリンク先の選択のみ。位置が埋まっているグループにはリンクできない
- 離脱置換: イベント適用前に、離れるグループのイベントの対象を「選んだ1枚」に書き換える。残りは残り、1枚になればリンク解消
- 条件: 式 `link_count`（自分のリンク枚数）を追加
- タップ状態はグループ全員で共有する

既知の制限:

- 他のカードの常在型（「ゴッドすべてを+1000」など）はメンバーごとに適用されてから合算されるため、グループ全体への修整が枚数分だけ重なる場合がある
- 「カード3枚でリンクしていれば、リンクしているゴッドは離れない」のような離脱そのものの禁止は未対応
- リンクした瞬間だけを見る誘発（「リンクした時」）は、出た時の誘発＋link_count 条件で代替する

対象: rejects の g_link 単独ギャップ 120件。全件がゴッドのリンク機構そのものを要求する。

## ルールの要点（rejects 文面から）

- ゴッドは「左G・リンク」「中央G・リンク」「右G・リンク」のいずれかを持つ
- 中央: そのゴッドが出る時、まず自分の好きな数のゴッドからカードを1枚ずつリンクを外してもよい。その後、そのゴッドを右または左リンク持ちのゴッドにリンクしてもよい
- 左（右）: 出る時、中央または右（左）リンク持ちのゴッドの左側（右側）にリンクしてもよい
- リンクしたゴッドは、各ゴッドの特性（パワーや能力）をすべて持つ1体のクリーチャーとなる。パワーは合計
- 離れる時は、その中から1枚を選んで離す（残りはバトルゾーンに残る）
- 「カード3枚でリンクしていれば／した時」「リンクしている間」を条件にする効果がある

## 現エンジンとの距離

- バトルゾーンの「1体」性は bz_tops（進化スタックの一番上）で表現されている。リンクは進化のような上下関係ではなく対等なグループなので、under/top_of の流用はできない
- 特性計算 chars() は1枚単位。リンク時はグループ全員の合算・統合が必要
- ゾーン移動はカード単位。グループの離脱置換（1枚だけ離す）が要る
- 出た時のリンク手順は、召喚解決直後の専用ステップとして割り込む必要がある

## 実装フェーズ

### Phase 0: 表現の決定とキーワード定義

- Card に link グループの印を持たせる（グループIDと、グループ内での左右位置）
- keywords.yaml に left_g_link / center_g_link / right_g_link を定義する（印として。手順はエンジン側）
- 決めること: グループの「代表カード」をどう置くか（攻撃・ブロック・対象選択でグループを1体として扱うための代表の決め方。中央を代表にし、中央が離れたら残りから引き継ぐ案が素直）

### Phase 1: 特性の統合（chars）

- リンク中のカードの chars をグループ統合にする: パワーは合計、キーワード・許可・禁止・ブレイカーは全員の和集合、種族・文明・タイプは和集合、能力（誘発・常在・起動）も全員のものがグループとして機能する
- コスト参照（「このクリーチャーのコスト」）は合計にする
- 対象選択・攻撃・ブロックでグループが1体として数えられるよう、bz_tops 相当の列挙をグループ単位にする

### Phase 2: 出た時のリンク手順

- ゴッドが出た直後にリンク手順ステップを挟む: （中央）リンク外しの選択 → リンク先の選択、（左/右）隣接する相手へのリンク選択
- リンクした瞬間の誘発（「3枚でリンクした時」）が発火するよう、リンク確定をイベントにするか、手順の終わりで条件誘発を拾う

### Phase 3: 離脱の置換

- グループのクリーチャーがバトルゾーンを離れる時、かわりにグループの中から1枚を選んでその1枚だけを離す（破壊・バウンス・除外など全ての離脱が対象）
- 1枚離れた残りが2枚以上ならリンク継続、1枚になればリンク解消

### Phase 4: 条件と継続効果

- 条件式に「自分のリンク枚数」を追加する（「カード3枚でリンクしていれば」用）
- 「リンクしている間」の常在型は Phase 1 の統合で自然に効く想定だが、発生源が離れた場合の扱いをテストで固定する

### Phase 5: 検証

- proto に左・中央・右の試験用ゴッドを用意し、リンク手順→統合特性（パワー合計・能力共有）→攻撃→離脱置換の全サイクルをテストする
- 代表カードを2〜3枚 parse で確認する（「黒幕」、無法神類 G・イズモ、双魔左機 ミルクなど）
- docs/vocab-pilot.md に第N弾として記録する

## 規模感とリスク

- 語彙パイロットで最大の弾。状態・特性・移動の3層に触るため、1弾で全部ではなく Phase 1〜3 を最小構成として先に通し、Phase 4 を続ける分割も可能
- 既存の進化・スタック処理への波及が最大のリスク。全体テスト（約490件）の回帰確認が前提になる
- 数の条件（「カードが4枚以上含まれていなければ」＝進化の下カード数と同種の条件）など、ゴッド個別の追加条件はカード側の表現で吸収できる範囲を Phase 4 で見極める
