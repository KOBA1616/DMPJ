# 速い候補の中からループしうる組を探す（2026-11-13）

絞る順番を逆にした: 先に速さの上限（`dmsim/eval/speed_bound.static_bound`）で 4T 以内に入口へ届きうる組を母集団にし、その中でつながりの点・静的なループ判定・物差しを当てた。
道具: `tools/fast_loop_screen.py`（段1〜2）、`tools/fast_loop_measure.py`（段3）。既定の挙動・日次の経路は変えていない。holdout は使っていない。

## 1. 母集団とつながりの点の分布
2枚組の候補 1,842,017 組（順序なし。札 9,691 枚、効果データの形が想定外の10枚は除く）。上限ターン: 1T 412 / 2T 11,402 / 3T 129,989 / 4T 278,689 / 5T 370,578 / 6T 343,009 / 7T以上 584,428 / 不明 123,510。

|---|---|---|---|---|---|---|
| 速い（4T以内） | 420,492 | 5.71 | 5.11 | 7.79 | 12.79 | 19.52 |

分布の本体はほぼ同じで、違うのは最上位の尾だけ（点 19.5 を超える組はすべて遅いか不明）。前回「上位200組」に速い組が3組しか残らなかったのはこの尾のため。

## 2. 静的なループ判定（`engine.zone_graph` の循環を2枚の束の中だけで探す）

3枚組: 勝ち手段がない 365 組の上位200組に、閉路の移動で誘発し相手のゾーンを動かす札を1枚足した（1組あたり上位20枚まで）。4T以内の3枚組 2,322。
静的な判定は過大近似（コピーの所在・召喚酔い・置換・継続効果を見ない）で、「条件つき」の移動も起きる前提で数える。

## 3. 物差しと上限ターンの実測
汎用の入口局面（自分4T目相当、マナ5、部品を手札とマナに1枚ずつ、相手は入口局面と同じ・マナチャージだけ）で、8シード・予算1500。上限ターンは山札が見える探索で3並び×先後、予算300、4Tまで。

| 組 | 組数 | 段1に届いた組 | 段2に届いた組 | 4T以内の勝ち（実測） |
|---|---|---|---|---|
| 2枚組の上位 | 40 | 2（墓守の鐘ベルリン＋エール・ライフ、同＋スパダチ・ジェネレーション!!!、どちらも 8/8） | 0 | 0 |
| 3枚組の上位 | 10 | 0 | 0 | 0 |
| ランダム（4T以内の組から） | 50 | 0 | 0 | 0 |

段1ではランダム組と差が出た（2/40 対 0/50）が、段2はどちらも 0。ベルリンの2組は「マナに置く→場のものを壊す」を回せても、相手のゾーンを動かす移動が相手のクリーチャーの除去で、相手の場が空なら勝ちに変わらない。

## 4. 何も登録できなかった理由（次の方針の材料）
- 最も多く落ちるのは閉路がない（87%）。次が札が狙って戻らない（7.5%）。2枚で閉じる組は 415 組まで減り、勝ち手段まで持つのは 50 組。
- 静的に残った組でも、実エンジンでループとして回るのは2組で、どちらも勝ち手段がない（除去しか動かさない）。勝ち手段の判定を「相手の山札・盾を動かす」に狭めるのが次の候補。
- 効果データが未対応で局面が作れない・対局が落ちた組は 0。
- 未承認カードの印: `load_rules(only_approved=True)` で読める実カードは今1枚だけなので、残った組はすべて未承認カードを含む（印は `unapproved` 欄）。承認の進み具合しだいで結果は読み直しが要る。
