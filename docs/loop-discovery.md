# ループと手順の自律発見（設計と v1 の結果）

AIが、独自のループを発見し、初期盤面からループ導入とループキルまでの手順を見つけ、
その手順を再利用できる台本（方策）として抽出するための設計と実験結果。
実装は `tools/discover_pipeline.py`。

## 学習の2層分離

プレイの判断は、粒度の違う2層に分けて学習する。混ぜると、学習対象も評価軸も曖昧になるため。

### マクロ（大局観）― ターンの狙い

ターン（あるいは局面）の単位で「このターンは何をするか」を決める層。

- 狙い（intent）の例：見切り発車してでも攻める／手札とマナを整える／リーサル（ループキル）を
  狙う／相手を妨害する（ロック・資源を削る）
- 入力は局面全体の特徴：ターン数、手札・マナ・山札の枚数、目標ループの部品が
  どのゾーンにあるか、相手のシールドと山札
- 出力は狙いと、それに伴う探索の動かし方（予算、ストック方針、目標部品）
- 学習対象は「特徴 → 狙い」の対応。評価軸は狙いごとの到達率・勝率
- 実装：`MacroPlanner`（v1 はサガループ目標の規則ベース。setup / enter_loop / execute を切り替える。
  disrupt は相手モデルが簡易なため将来の拡張）

### ミクロ（詳細）― ターン内の決定

個々の決定をどう答えるかの層。

- 対象：カードのプレイ順、ループの手順（捨てる札・蘇生先・対象の選択）、
  唱える／出してよいか否か、リソース（マナ・山札・キーパーツ）の温存
- 入力は決定の種類と文脈、出力は選ぶキー（候補の順序付け）
- 学習対象は「決定の種類と文脈 → 選ぶキー」の選好。評価軸は探索ノード数と勝率
- 実装：`MicroPolicy`（v1 は決定の種類ごとのキー選好率。文脈条件付きが次の拡張）

大まかには、マクロが「どの山を登るか」を決め、ミクロが「足の置き方」を決める。
探索（TurnSearch）は両層に挟まれ、マクロの狙いの下でミクロの案内を受けて手順を探す。

## パイプライン

1. ゾーン変換グラフでループ候補を静的に列挙する（`zone_graph.find_cycles`）
2. 初期盤面から探索の収集モードでループ証明書を動的に発見し、再生で検証する
   （`loop_first.discover_loops`）
3. 教師（最初は既存の台本）で案内した探索の勝ち手順を、最初から再生しながら
   決定データ（種類・選択肢・選んだキー）を収穫する
4. 収穫データからミクロ選好を学習し、方策ファイル（JSON）に出す
5. 学習方策だけで案内した探索を、未使用シードの初期盤面で検証する
6. マクロが狙いを切り替える階層版でも検証し、ミクロ単独と比較する

## v1 の結果（サガループ中心、2026-10-26）

条件：手札サガ・コダマ・イザナギ等、墓地タイフーン・サガ、山札18枚に
ドラゲリオン／イワシン／シャコガイルを乱数位置へ挿入した初期盤面。
勝ち＝そのターンのうちの勝利。探索予算は TurnSearch 3000。

| 段階・方式 | 結果 |
|---|---|
| 候補列挙 | 869件（max_cards=2） |
| 動的発見 | 初期盤面5件から相異なるループ5種、うち3種が再生検証済み |
| 手順の収穫 | 訓練盤面20件で13勝、決定レコード790件 |
| 案内なし探索 | 0/20勝（平均2,214ノード） |
| 台本単体 | 11/20勝 |
| 台本で案内した探索 | 13/20勝（平均397ノード）、未使用シードでは15/30勝 |
| 学習方策（ミクロ）で案内した探索 | 未使用シードで15/30勝（平均604ノード）。人の台本と同等 |
| マクロ＋ミクロの階層版 | 未使用シードで15/30勝（平均604ノード）。この盤面群ではマクロの狙いが全件 enter_loop になり、ミクロ単独と一致した。狙いの差が出るのは、部品の揃い具合が混ざった盤面群で測る必要がある |

学習済み方策の例は `tools/loop_policy_saga.json`（段階4の出力）。

## v2（階層の精密化）

- マクロ v2：特徴に墓地の準備（起点カード／タイフーンが墓地にあるか）、闇マナの枚数、
  導入部品の手札枚数を追加。enter_loop は「起点＋墓地の準備＋闇マナ」が揃った場合だけにし、
  setup では山札を削らない設定（ストックなし、山札を守る重み、予算を絞る）でターンを渡す
- ミクロ v2：選好を文脈（山札の厚さ thin ≤8 / mid 9–18 / thick ≥19）ごとに分けて学習し、
  全体の選好に重ねる。収穫レコードに決定時点の山札枚数を記録する。v1 形式の方策ファイルも読める
- 測定：揃い具合の違う初期盤面群（`tools/minimal_setup.py` の12配置×8試行、予算2000、
  勝ち＝そのターンの勝利）で、案内なし／ミクロ単独／階層版を比較した

| 配置群 | 案内なし | ミクロ単独 | 階層版 |
|---|---|---|---|
| A（導入部品と墓地の準備が完了） | 0/8 | 6/8（340ノード） | 6/8（狙い enter_loop） |
| B1〜B3（部品の一部が山札） | 0/24 | 8/24 | 8/24（狙い enter_loop） |
| C・D系（ブルース経由、サガは手札のみ） | 0/64 | 0/64 | 0/64（狙い setup） |

読み取れること：
- ミクロの案内は、サガが墓地にいる系（A・B）では同ターン勝ちを 0 → 8〜75% にする
- ブルース経由の系（C・D）は全方式 0勝。STATUS で導入台本の後半が未確認とされる経路で、
  学習方策の訓練範囲（A系）にも入っていない。別の手順の発見が要る
- マクロは配置群ごとに狙いを正しく切り替えたが、この単一ターンの測定では勝率は
  ミクロ単独と変わらず、差は計算量に出た（setup の配置では予算を絞り、
  C2 で 688→480 ノード）。「整える」が報われるのは複数ターンの対戦で測る必要がある
- ついでに見つけた不具合：MicroPolicy を Pipeline を経由せず単独で差し込むと
  候補生成が無限再帰した（v1 から）。原関数を読み込み時に退避するよう直し、回帰テストを追加

## v3: 勝ち方を文脈に入れる

勝ち方が違えば、同じ局面でも守るべきものが逆転する。置換勝利（自分の山札切れを
効果で勝ちに変える）では自分の山札が命綱だが、相手の山札を削る型では自分の山札は
消耗品で、シールド0型では相手のシールドと打点が全てになる。v3 はこの勝ち方を
マクロ・ミクロ双方の文脈として持たせる。

- 勝ち方の分類 `classify_win`: 検出器の `analyze` が出す `opp_deck_out` /
  `shield_zero` に加え、win_by=None でも検証で勝てていれば `effect`（置換勝利など
  効果で勝つ）、そうでなければ `resource`（資源を増やすだけの循環）と分類する。
  段階2のカタログの win_by もこの分類で記録する
- マクロ: 特徴に `win_by` を追加。setup の山札保護は effect の時だけ厚く
  （deck_keep=18、ストック禁止）、相手を削る型では消耗を許す（deck_keep=2）。
  execute の評価の重みも勝ち方で切り替える（shield_zero はシールドと打点、
  opp_deck_out は相手の山札、resource は手札とマナ）
- ミクロ: 選好の文脈を「勝ち方×山札の厚さ」（by_context）に拡張した。
  重ね順は 全体 → 厚さ区分 → 勝ち方×区分 で、文脈が一致した選好が最優先になる。
  決定レコードにも勝ち方を記録する。方策ファイルは format 3
  （`tools/loop_policy_saga.json` はサガ=effect として移行済み。旧形式も読み続けられる）

狙いは転移の土台である: 特徴と文脈がループ固有のカード名ではなく勝ち方と
局面の形で書かれているほど、別のループで学んだ選好が効くようになる。

## 複数ターンの対戦での評価（v3）

「整える」狙いが報われるかを見るため、配置から始めて自分のターンを最大3回まで
回した（相手はマナチャージのみ、配置あたり6試行）。

| 配置 | 通常探索 | ミクロ単独 | 階層（マクロ＋ミクロ） |
|---|---|---|---|
| A（サガが墓地） | 5/6（キルは1〜2ターン目、1826ノード） | 6/6（全て1ターン目、182ノード） | 6/6（182ノード） |
| C2（ブルース経由） | 2/6（キルは2ターン目） | 2/6 | 2/6（931ノード） |
| D3（ブルース経由・墓地なし） | 1/6 | 1/6 | 1/6 |

- A系ではミクロの効果が複数ターンでも支配的で、通常探索より速く確実にキルへ届く
- ブルース経由は、勝てる場合でもキルは2ターン目。導入とキルが別ターンに分かれる
  2ターンの手順であることが分かる（次節）
- マクロの setup は、この範囲（3ターン・無抵抗の相手）では勝率を押し上げなかった。
  v3.1 でブルース経由の材料が揃った局面を enter_loop と判定するようにはしたが
  （従来は setup と誤判定）、勝率はミクロ単独と同水準。setup の利得は、
  相手が妨害してくる条件や、もっと長い対戦で測る必要がある

## ブルース経由の手順発見（v3.1）

サガが1枚しかない系（C・D系、全方式0勝だった）の手順を教師化して確かめた。
筋は、サガ登場→手札のイザナギを捨てて蘇生→イザナギの「上から5枚を見て1枚加える」
で山札のサガや部品を探す→イザナギの踏み倒しでブルースの呪文面を唱え、墓地のサガを
場に戻す、というもの。

- 教師単独実行: C1〜D5 と「山札にもサガ」の全9配置×4試行で、導入（ブルースが
  呪文面で墓地へ行き、サガが場に戻る）まで 36/36 到達
- ただし同ターンキルは 0/36 で、教師優先の案内探索でも 0/4。導入のターンのうちに
  キルまで届く手順は見つからなかった
- 複数ターンでは2ターン目にキルへ届く場合がある（C2 で 2/6）。つまりこの経路は
  「導入ターン＋キルターン」の2ターン手順として扱うのが正しい
- マクロ v3.1: 特徴に `bruce_route`（起点＋掘る役＋ブルース呪文面が手札）を追加し、
  墓地の準備が無くても enter_loop と判定する

## v4: 1ターン目からの通し対戦と、ミクロ文脈の拡張

これまでの測定はすべて「3ターン目相当の配置」（タイフーンで墓地にタイフーンと
サガが落ちた後）からだった。サガループの実戦は、整えるターン（タイフーン系で
手札を整えつつ墓地にクリーチャーを用意する）とループ手順の組み合わせなので、
実カード中心の近似デッキ（40枚、残りは基本セットの単色カードで近似）を組み、
1ターン目から通しで対戦させた（相手はマナチャージのみ、自分のターン最大8回、6試行）。

| 方式 | 勝ち | キルの自分ターン | タイフーン使用 | ノード平均 |
|---|---|---|---|---|
| 通常探索 | 6/6 | 5〜7 | 3/6 | 3343 |
| ミクロ単独 | 5/6 | 5〜6 | 1/6 | 3087 |
| 階層 | 5/6 | 5〜6 | 2/6 | 2089 |

- 通し対戦でも勝ち筋は再現でき、タイフーンで墓地を貯める勝ち方も現れる。
  ただし台本の最速（3ターン目キル）より遅く、5〜7ターン目に寄る
- 学習したミクロは通し対戦では勝率を押し上げなかった。訓練データがループの
  ターンだけなので、整えるターンの決定には訓練範囲外の選好が効いてしまう。
  階層版は計算量だけは約4割減った

そこでミクロの文脈を拡張した（v4）。文脈は「勝ち方×そのターンの狙い×
墓地のクリーチャー数（蘇生条件の3体以上か）×山札の厚さ」で、狙いはマクロが
ターンごとにミクロへ渡す。収穫レコードにも狙いと墓地区分を記録するようにし、
再学習した方策（format 4）では狙い付きの文脈が実際に生成された。ただし
整えるターンの文脈はまだデータが無い（収穫がループのターンだけのため）ので、
通し対戦の数字は変わらなかった。次は複数ターンの勝ち手順そのものを収穫対象に
広げることが要る。

## v5: 山札の扱いを「尽きる時だけ悪い」に直し、ループ以外の戦術を足す

設計の見直し3点。

1. **山札保護の基準を変えた**。以前は setup で山札を18枚より減らさないという
   固定の厚さを守っていたが、山札が悪いのは「コンボを決める前に尽きて負ける」
   時だけである。deck_keep は全勝ち方で2（山札切れの直前だけ守る）にし、
   execute の条件からも山札の厚さを外した（部品が揃えば取りに行く）。
   置換勝利で残したのは、勝敗に直結しない資源ループの自動反復の停止だけ。
2. **山札の厚さを確率の特徴に変えた**。特徴に `pieces_in_deck`（公開領域を
   引いた残りの山札に、欲しいカードが何枚残っているか）と `dig_hit_prob`
   （上から5枚を見て欲しいカードが少なくとも1枚ある確率）を追加した。
   厚さそのものではなく「掘って当たる見込み」で判断する材料にする。
3. **ループ以外の狙いを追加した**。盤面の打点でリーサルが見えれば execute
   （殴り切り）、打点があれば beatdown（シールドを削る）、相手の圧力が高ければ
   control（盤面を捌いてターンを稼ぎ、手札とマナを整える）。

効果は複数ターンの測定で出た（同じシード・配置、階層版）:

| 配置 | v4まで | v5 |
|---|---|---|
| A（サガが墓地） | 6/6 | 6/6 |
| C2（ブルース経由） | 2/6 | 6/6（狙いの列: enter_loop → beatdown → execute） |

通し対戦（1ターン目から）でも、setup → beatdown → execute と殴り切る勝ち筋と、
setup → enter_loop → execute のループの勝ち筋の両方が現れるようになった。
execute の厚さ条件を外したことで、ブルース経由の2ターン目以降に予算が
届くようになったのが大きい。

## v6: サガの条件の検証、確率の実測、マナチャージの判断

**サガの「墓地にクリーチャー3枚以上」**は実装されている。カード定義の条件として
入っており、実地でも確かめた: 墓地クリーチャーが条件に届かない状態でサガを出すと
「引いて捨てる」だけが起きて蘇生は発動せず、サガは場に残る。なお判定は捨てた後なので、
サガ自身の捨て札がクリーチャーならその1枚も数に入る（墓地2枚からでも発動しうる）。

**最速ラインの確率**を、タイフーン2種8枚（エマージェンシー・タイフーンと
ローレンツ・タイフーン）と1種4枚で比べた（マナ0から、台本200試行＋探索24試行）。

- 2ターン目にタイフーン系を撃てる割合は 8枚で 78/200、4枚で 74/200 と大差ない。
  律速はタイフーンの枚数ではなく、サガ2枚とイザナギと文明が同時に揃うか
- 台本では5ターン以内のループ勝ちは両デッキとも0。探索では5ターン以内の勝ちは
  全部ダイレクトアタック（8枚 8/24、4枚 11/24）で、ループキルは通し対戦の
  5〜7ターン目に現れる。3ターン目ループキルは再現可能な最速ラインだが、
  ランダムな引きでは今のところ観測できていない低確率のまま

**3ターン目コダマダンス**（シールドを1つ戻し、チャージャーでマナに残して
4ターン目5マナにする）は、台本では約3割で撃てた。ただしマクロの明示的な
戦術としてはまだ入れておらず、探索がマナ評価で拾うだけに留まる。

**サガを掘り役として使うプレイ**は、素の探索には既にある。ループが決まらない
局面（墓地クリーチャー1枚・部品なし）でも、探索はサガを出して「引いて捨てる」で
手札を整えることを選んだ。マクロ／ミクロの設計として明示的には扱えていない。

**マナチャージの判断**をミクロに実装した（`charge_scores`）。スコアの考え方は
「手札で失う価値が小さく、マナとして困らない札から置く」:

- 目標の部品は温存する（同名が2枚以上ある場合だけ候補に戻す）
- 既にマナにある文明しか持たない札（特に多色で新しい文明が増えない札）は置きやすい
- 直近2ターンで使えないコストの札は置く候補にする
- マナに無い文明を持ち、手札が必要としているなら、補完として置く価値がある

## v7: ビートダウンの抑制は大局観レベルに。文明への動機とチャージのバランス

**ビートダウン抑制の形を見直した。** 狙いのレベルで抑制しても探索は殴りに
流れたため、一度は攻撃の決定自体を止めてみたが、結果は 0/16 と全敗だった。
ドラゲリオンのメテオバーンのような攻撃時効果まで止まってしまい、ループの
勝ち筋そのものが壊れる。そこで抑制は「大局観レベルの方針」に戻した:
マクロは beatdown を選ばず、ミクロは攻撃の候補を後ろに回す（pass を先に置く）
だけにして、リーサルや攻撃時効果が必要な筋は探索が拾えるようにした。
この形では勝率は 16/16 に戻った。

**マナの文明への動機**を評価関数に足した（`Weights.civ`、既定0で従来通り。
マクロの setup / enter_loop / control が正の重みを使う）。チャージ判断にも
バランスの規則を2つ足した:

- このターン出したい札に必要な文明を、その1枚で補えるなら優先する
  （単色を埋めてこのターンのプレイを通す判断）
- 多色カードが手札に3枚以上溜まっていたら、多色から先にマナへ置く
  （将来アンタップできるマナが細る前に、柔軟な札をマナに回す）

これらは今はルールの採点として入っている。学習への移行のため、収穫レコードに
文明の文脈（マナの文明数・手札の多色枚数）を記録するようにした。選好の学習が
進めば、採点の重み自体をデータから調整できる。

**こだまダンス戦術の発見度合い**（タイフーン2種8枚、通し16試行）:
「setup のターンにコダマダンスを唱え、次のターンにマナ5以上」は、抑制なしで
1/16、方針レベルの抑制で 3/16、攻撃を止めた条件では 7/16 に現れた。
マナ加速のプレイ自体は探索が見つけている。ただし通し対戦でのループ勝ちは
まだ 0 で、勝ちは攻撃側に寄っている。ループの勝ち筋が通し対戦の予算内で
見つかるようにすることが残課題（中盤の配置からは階層版が届いている）。

## v8: チャージのバランスを連続的な損得に。掘りながらの導入と、通し対戦の検証拡張

**チャージ判断から固定の枚数条件を無くした。** 「多色が3枚以上なら多色を置く」
のような決め打ちはやめ、多色を置く動きやすさは手札の多色の枚数に応じた
連続的な損得にした。位置によって両方の戦術が取れる:

- 文明が揃っていて多色がプレイできる位置では、単色側を置いて多色を残す
  （単色のドローを期待して多色をプレイする方針）
- 置きたい単色のプレイがある時は、それを残すために多色側を置く
- 多色が多いほど、1枚置く痛みは相対的に小さい

最終的な釣り合いは、勝ち筋から収穫した選好の学習に委ねる前提で、
規則はあくまで初期値（事前分布）として置く。

**導入の条件を広げた。** 部品が全部手元に無くても、手元の部品が2種以上あり、
残りが山札にあって5枚掘りの当たる確率が5割を超えるなら「掘りながら導入」
（enter_loop、予算3000）する。最小部品4種が手元に揃った（ループの最小盤面）
ターンでは、変換に計算を寄せる（予算4000）。

**通し対戦の検証拡張**（タイフーン2種8枚、24試行、相手はチャージのみ）:

| 条件 | 勝ち | うちループ（置換）勝ち | 最小盤面に到達 | 導入ターン数 |
|---|---|---|---|---|
| 掘りながら導入なし | 24 | 3 | 10（平均5.1ターン目） | 25 |
| 掘りながら導入あり | 24 | 2 | 9（平均5.0ターン目） | 90 |

読み取れること:

- 通し対戦でもループ勝ちは起きるようになった（24試行中3件）。
  最小盤面への到達は約4割で、到達した対戦の3割ほどがループ勝ちに変換される
- 「掘りながら導入」は導入ターンを大きく増やしたが、ループ勝ちは増えなかった。
  早すぎる導入は変換率を上げない。狙いを立てること自体より、
  最小盤面に届く割合と、届いた後の変換が律速になっている
- 変換ターンでも、探索が攻撃の勝ちを見つけるとそちらを取ることがある
  （実戦では正しいが、ループ勝ちの割合としては下がる）

次の律速は、部品がシールドやマナに埋まって最小盤面に届かない対戦を減らすことと、
到達後の変換率を上げること（キル部品の墓地条件を導入の段階から意識させる）。

## v9: 診断で律速を切り分け、到達の数え方と墓地準備と再学習を入れた

「安定しないのは学習不足か」を、言葉ではなく対戦の中身で切り分けた
（タイフーン2種8枚、通し24試行）。

**攻撃勝ちの中身**: 22件の攻撃勝ちのうち大半は「導入（enter_loop）のターン」に
起きていた。部品を集める過程で場にクリーチャーが並び、探索がそのまま
リーサルを見つけて殴り切る。最小盤面に届いた対戦でも、届いた盤面は
打点も揃っているため、攻撃で決着することがほとんどだった。

**ループ成立を優先する実験**: 最小盤面に届くまで攻撃しない方針
（`MicroPolicy.loop_priority`）にすると到達は 9→16 に増えたが、
攻撃勝ちは減らなかった（到達後に攻撃が解禁され、そのまま殴り勝つ）。
到達ターンにループ手順の探索（`try_loop_first`）を先行させても、
検証済みループが見つかる位置は限られた。個別に調べると:

- 「到達」と数えた盤面に、サガやドラゲリオンが**マナに埋まって**いる対戦があった
  （マナの部品はループに使えない。到達の数え方が緩かった）
- 部品が揃っても**墓地の準備が無い**（墓地クリーチャー3枚などの前提が未達で、
  ループが回り始められない）対戦があった

そこで v9 では:

- 最小盤面の数え方を直した（手札・場・墓地だけを数え、マナは除く）。
  厳しい定義での到達は 13/24
- 導入のターンで墓地が足りない間は、捨てる選択でクリーチャーを優先して
  墓地に送る（墓地準備を寄せる）
- 通し対戦から判断を収穫する `Pipeline.harvest_games` を追加した。
  旧方策は序盤〜中盤の文脈が空で、これが学習不足の実体だった。
  到達した対戦とループ勝ちした対戦から 970 件を収穫して学び直すと、
  総勝率は 21→24 に戻り、ループ勝ちは 3 件を維持した

| 構成 | 勝ち | ループ勝ち | 攻撃勝ち | 最小盤面に到達（厳密） |
|---|---|---|---|---|
| v8（抑制は順序のみ） | 24 | 2 | 22 | —（緩い定義で9） |
| ループ優先のみ | 24 | 2 | 22 | —（緩い定義で16） |
| v9（数え直し＋墓地準備＋手順先行） | 21 | 3 | 18 | 13 |
| v9＋通し対戦で学び直した方策 | 24 | 3 | 21 | 12 |

**残る律速はマナ埋没**。厳密に届いていない対戦の大半は、部品のどれかが
マナにあって使えない。次は「最後の到達可能なコピーをチャージで守る」
判断の強化と、マナから部品を戻す手段の確保が対象になる。
学び直した方策ファイルの差し替えは、配置型の評価（A系・ブルース経由）で
退行が無いことを確かめてから行う。

## v10: リーサルの出所を確かめ、不要なプレイへのペナルティとパーツ保護を入れた

**仮説の検証（召喚酔い）**: 攻撃勝ち18件を調べると、17件は最終ターンの開始時点で
「前のターン以前に出ていたクリーチャーの打点だけ」でリーサルが足りていた。
そのターンに出た部品は召喚酔いで殴れないので、リーサルは到達したターンの
プレイではなく、過去のプレイの蓄積で作られていた。攻撃していたのは
余分に出したイザナギやブルース、イワシン、基本セットのクリーチャーなど。

そこで次を入れた:

- **不要なプレイへの微小なペナルティ**: 成立優先の間、戦略に必要なプレイ
  （部品・掘る呪文・マナ加速）以外のプレイを候補の後ろに回す。
  部品集めの挙動には与えない
- **到達の条件の調整**: 「回り始められる状態（loop_ready）」を、部品の到達に
  墓地クリーチャー3枚の前提を加えたものにし、攻撃の解禁とループ手順の
  先行はこの条件で判定する
- **メインパーツの保護強化**: チャージでは、干渉できるゾーン（手札・場・墓地）に
  残る同名の枚数を数え、メインパーツ（サガ）は2枚、その他の部品は1枚を
  切る置き方をしない。必要最低限のパーツの価値を、チャージ面で高くした

**測定結果（通し24試行）**: 勝ち22、ループ勝ち2、攻撃勝ち20、到達12。
ペナルティの効果は誤差の範囲で、攻撃勝ちは減らなかった。理由は境界の引き方で、
リーサルを作る体の大半は「部品そのもの」だった（掘るために出したイザナギが
場に残る、など）。候補の順序程度の弱いペナルティでは、探索は必要なプレイの
副産物である打点まで消せない。強く効かせるなら、葉の評価で「戦略に不要な
常駐打点」を数えて引く形が要る（次の対象）。

パーツ保護の側は、終了時点で部品がどこにも無い対戦はドラゲリオンが
シールドにいる1件だけになった。

## v11: 攻撃勝ちの盤面の正体と、報酬の自動設計

**攻撃勝ちの盤面報告**（最終ターン開始時点、全20件）: 16件で
「冥界の不死帝 ブルース」が場に立っていた。このプールではブルースは
2コスト・パワー13000・トリプルブレイカーで、1体で3打点、2体で6打点になる。
残りはイワシン・イザナギ・アクア・ハルカスなどの1打点を2〜3体足した形。
6打点は「ブルース＋端数」で揃ってしまい、墓地の溜まりとはほぼ無関係だった
（ブルースは呪文面でなく、安い大型として出されたプレイが打点化している）。

**報酬の自動設計**（`learn_play_shaping`）: 「寄与するプレイ」を人手で列挙する
代わりに、成功した対戦の軌跡から学ぶ。収穫レコードに勝ち方（result）を
持たせ、狙う勝ち方で勝った対戦だけから出現率を数える。到達した対戦の多くは
攻撃で終わるため、混ぜて学ぶと打点用のプレイまで高報酬になってしまう
（実際、混ぜた版ではブルースが0.92と最上位級になった）。勝ち方で絞った
報酬表（ループ勝ち4試合から）は、タイフーンとサガが1.0で最上位に来た。

| カード | 報酬（ループ勝ちのみ） |
|---|---|
| エマージェンシー・タイフーン / 絶望神サガ | 1.0 |
| ブルース / ローレンツ・タイフーン / ドラゲリオン / 基本の闇 | 0.75 |
| コダマダンス / イザナギテラス | 0.5 |

**測定（通し24試行）**: 勝ち23、ループ勝ち3、攻撃勝ち20、到達14。
到達した対戦からループ勝ちに変換できたのは2件（v9・v10は1件）。
総勝ち・到達・変換はいずれも現状で最良のバランスだが、攻撃勝ち自体は
減っていない。報酬表がカード単位（面を区別しない）ため、ブルースの
呪文面（ループに必要）とクリーチャー面（打点）を分けられていないのが一因。
標本もループ勝ち4試合と少なく、表は粗い。面まで区別した報酬と、
勝ち方の内訳を増やす収穫が次の対象。

**収穫の増強**: 収穫側の対戦にも、手続き先行（try_loop_first）を接続した
（到達済みで墓地クリーチャー3体以上のターンに限る）。勝ち筋の軌跡が
増え、学習材料そのものが厚くなる。

**指定レシピでの試行**（サガ4／タイフーン2種各4／イワシン4／イザナギ4／
ブルース4／シャコガイル2／ドラゲリオン2／こだまダンス4／基本セット8）:
96試行を収穫し、保持57試合・記録3862件、ループ勝ちの記録は358件まで
増えた。ループ勝ちだけから学んだ報酬表は、ブルース／ドラゲリオン／
サガが1.0、イザナギ0.6、タイフーン／こだまダンス／基本の闇が0.4。

**新しい種（4000番台、32試行）での比較**:

| 条件 | 勝ち | ループ勝ち | 攻撃勝ち | 到達 |
|---|---|---|---|---|
| 旧デッキ＋従来の方策 | 28 | 1 | 27 | 21 |
| 指定レシピ＋従来の方策 | 24 | 0 | 24 | 19 |

入ってからが本番。

## v13: 相手のシールドをすべてデーモン・ハンドに

相手デッキは dm01-027 ×40 で、現在のカードデータでは dm01-027 は
デーモン・ハンド（S・トリガー／相手のクリーチャーを1体破壊）そのもの。
つまりシールドはもともと全部デーモン・ハンドだったが、相手役が
トリガーを常に使わない選択をしていたため、除去は一度も発動して
いなかった。今回、トリガーを使う相手役（trigger_opponent_policy）を
実装した：トリガーは全部宣言し、破壊の対象は「ループの主部品 →
パワーの大きい順」で選ぶ。探索の中の相手の判断と、収穫側の対戦にも
同じ相手役を接続できる（harvest_games の opp_policy）。

確認：種4004は、トリガーなしでは攻撃で勝っていた対戦が、発動ありでは
サガ3枚・イザナギ3枚を破壊され、ループ未完成のまま山札切れで敗北に
反転した。

**測定（種4000番台、32試行、トリガーなし → デーモン環境）**:

| 条件 | 勝ち | ループ勝ち | 攻撃勝ち | 到達 | 到達して負け |
|---|---|---|---|---|---|
| 旧デッキ＋従来の方策 | 28→23 | 1→1 | 27→22 | 21→27 | 1→6 |
| レシピ＋従来の方策 | 24→22 | 0→1 | 24→21 | 19→22 | 2→3 |
| レシピ＋新方策 | 27→24 | 0→1 | 27→23 | 18→23 | 2→4 |

読み: 環境は確かに厳しくなった（総勝ちは各条件で2〜5減、到達して
負ける対戦が増えた）。しかし勝ち方の内訳はほぼ変わらない。探索が
トリガーを読めるため、盤面を厚くしてから割り、破壊で減っても
ダイレクトアタックに届く分だけ残す、という適応が起きている。
到達率が上がったのは、攻撃の決着が遅れて対戦が長くなり、盤面を
揃える機会が増えたためとみられる。シールドの壁だけでは、AIは
ループに移行しない。ボトルネックは引き続き「到達した盤面から
回し切る」変換の段階にある。

## v14: 変換失敗の診断と、部品の「置き場所」の保護

到達したのにループ勝ちにならない対戦を、反事実の試行つきで分類した
（種4000番台、32試行）: 手順の失敗17、未到達11、準備不足3、
攻撃が先に取った1、ループ勝ち0。主因は「攻撃が先に勝つ」ことでも
「条件が厳しすぎる」ことでもなく、手順そのものの失敗だった。

失敗局面を段階ごとに切り分けると、候補は見つかることがあっても
検証を通るものが1件も無かった。部品の置き場所を見ると、ドラゲリオンが
墓地とマナにしかない局面が6件中3件、サガが手札にも場にもない局面が2件。
「最小盤面に到達」の数え方が、揃っているが置き場所が違って回り始め
られない局面を到達扱いしていた。特に、墓地の頭数を稼ぐための破棄が、
墓地から戻せないドラゲリオンを墓地に送っていた疑いが濃い。

対策: 到達の条件に配置を追加（ドラゲリオンは手札か場、サガは手札か場
またはブルースで戻せる形）。ドラゲリオンを破棄・チャージの犠牲に
しない（墓地の同名は「残せる枚数」に数えない）。ループ手順の発見と
仕上げにもミクロ方策の誘導を接続した。

**測定（種4000番台、32試行）**:

|---|---|---|---|---|
| 旧デッキ（v14前） | 28 | 1 | 27 | 1 |
| 旧デッキ＋v14 | 19 | 3 | 16 | 8 |
| レシピ＋新方策（v14前） | 27 | 0 | 27 | — |
| レシピ＋v14 | 17 | 2 | 15 | 8 |

ループ勝ちは増えたが、配置が揃うまで攻撃を自制し続けるため、揃わな
かった対戦で攻撃勝ちを取り逃がした。そこで自制に期限を入れた
（自分の7ターン目まで。8でも大差なかった）:

| 条件 | 勝ち | ループ勝ち |
|---|---|---|
| 旧デッキ＋v14＋期限7 | 23 | 1 |
| レシピ＋v14＋期限7 | 26 | 2 |

## v15: 入口の条件を実測から学ぶ／途中目標と準備の学習

指摘を受けて2点を改めた。

**情報の規律**: 実戦の判断は山札とシールドの中身を見ない。マクロの
特徴は、デッキレシピ（構築時点で既知）から公開ゾーンを引いた
「未見の札」に対する確率で計算するようにした。公開ゾーンが同じで
隠れた中身だけ違う2局面は、特徴が一致することをテストで担保する。

**入口の条件は手で書かない**: ループが開始できた局面（シナリオの確定
成功位置と実戦の成功1件）と、試して失敗した局面（7件）の公開記述
から、条件を自動で学ぶ仕組み（learn_entry_criterion）を入れた。
学ばれた条件は:

- サガが「手札＋墓地」合わせて2枚以上
- イザナギが「手札＋墓地」に1枚以上
- 墓地クリーチャー2体以上、マナ3以上

成功2件をすべて満たし、失敗7件をすべて弾く。墓地の頭数は失敗側も
全て3体以上あり、分かれ目は頭数ではなく「2枚目のサガが手札か墓地に
あるか」だった。これは、想定されていた最小単位（場のサガ＋墓地か
手札にもう1枚＋墓地2〜3体）のターン開始時点での形と一致する。

**途中目標と準備の学習**: 収穫は「ループ開始可能な局面に届いたか」を
対戦ごとに記録し、報酬の学習を「ループで勝った対戦」だけでなく
「途中目標に届いた対戦」からも行う。入口到達から学んだ報酬では
サガ1.0、ブルース0.958が上位で、ドラゲリオンは入口到達の軌跡に
現れなかった（組み立てでは出さず、ループの中で掘って連れてくる
部品だという形がデータにも出た）。

**測定（種4000番台、32試行）と方策の差し替え**:

| 条件 | 勝ち | ループ勝ち |
|---|---|---|
| レシピ＋入口学習方策 | 27 | 2 |
| 旧デッキ＋入口学習方策（転用） | 28 | 1 |

レシピ側は従来最良（26勝・ループ2）と同等以上、旧デッキ側も
従来の出荷方策（28勝・ループ1）と並び、初めてどちらのデッキでも
後退しなかったため、出荷方策を形式7（入口の条件つき）に入れ替えた。
ループ勝ち自体は2件どまりで、入口に届いた後の手順の実行（発見と
検証）が引き続き上限になっている。

## v16: 面単位の学習と、目的外の勝ちへの補正

ツインパクトは面で役割が違うのに、報酬がカード単位で混ざっていた。
報酬の学習を面単位でも集計するようにし、候補の順序付けは面の値を
優先して見るようにした（ブルースの呪文面は入口の道具、クリーチャー
面は打点、と分けられる）。

あわせて、目的の勝ち方でない勝ち（ループデッキのダイレクトアタック

## v18: 発火点の検証と単一条件の限界（2026-10-27）

## v19: ブルース経路の検証と Φ（局面ポテンシャル）の導入（2026-10-27）

発端は「ブルース上面が不当に高く、下面が評価されないのはなぜか」という
指摘。ブルース下面の価値は、最大のプレイであるサガ（墓地クリーチャー
2枚以上で蘇生が届く状態）を墓地から可能にする「引き継ぎ」にある。
頻度ベースの整形は相関しか測れず、この引き継ぎを表せない。

**検証1: 実経路の測定（レシピ／制限サガ〈サガ2枚〉、各96対戦）。**
経路の署名（イザナギ登場＋ブルース下面＋サガ帰還が同ターン）は両デッキで
0回。「ブルース下面＋サガ帰還」が起きた13ターンはすべて5ターン目以降で
墓地が6枚以上の状態、つまり組み立てではなくループ内の再利用だった。
機会（墓地にサガ＋手札にブルース）は87ターンあったが、経路には使われない。
サガを出すプレイ自体は、墓地2枚以上でキルが速い（平均5.0 vs 5.8ターン）。

**検証2: Φ（結果から学ぶ局面ポテンシャル、Suphx 型）。**
`fit_phi` / `phi_value` / `phi_leaf_bonus` を実装した。特徴は公開情報の
ゾーン別枚数に、引き継ぎを表す積（墓地のサガ×手札のブルース等）を加えた
もの。目的変数は時間割引つきループ勝ち。しかし自然な対戦データで学ぶと、
機会局面の Φ は平均以下になった。現在の方策がその局面を変換できないため、
結果から学ぶ価値は方策の盲点をそのまま映す。成功例が先に要る。

**検証3: コンボ直前局面（C/D 構築、山札順ランダム化、40種×8構築、2ターン）。**
教師（台本）はブルース呪文面を 40/40 で唱える（導入は常に達成）が、
2ターン以内のキルはほぼない（払い戻しは後続ターン）。学習方策は呪文面を
0/40（直前局面でも一度も選ばない）。教師順に並べ替えた探索も勝ちは
すべて攻撃で、呪文面は 0。候補の並びでは評価の谷を越えられず、
経路の中間局面の葉評価が攻撃路線に負けるためである。

**予算の切り分け（同種32試行）:** 探索予算 ×2 でループ勝ち 8→9、
×4 で 10、総勝ちは 31 で不変。予算は律速の一部だが主因ではない。

**結論と次段:** 経路は「実戦の頻度から学ぶ対象」ではなく「構成した局面から
成功例を作り、結果ベースの価値（Φ）で実戦側の接近局面に価格を伝える対象」。
次は、構築局面から教師に導入させた後に方策へ渡して完走させる収穫で
成功軌跡を作り、Φ を学び直して葉ボーナスにし、接近局面（タイフーンで
サガを落とす判断、ブルースを手札に残す判断）に価値が伝わるかを測る。

測定コードの教訓: エンジンの効果解決は判断をまたいで遅延するため、
ゾーン差分は1判断単位では取れない（ターン境界で取る）。
