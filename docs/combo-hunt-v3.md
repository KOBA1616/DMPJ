# コンボ発見 v3: 定義に沿った判定器（最小パーツ＋実リソースからの変換）

実装: `dmsim/discovery/hunt3.py`、実行: `tools/combo_hunt3.py`、テスト: `tests/test_hunt3.py`。
土台は v2（`dmsim/discovery/hunt2.py`。v2 の記録は hunt2 のモジュール冒頭と
`tools/combo_hunt2.py` の冒頭、および Kaggle 実行の記録 `~/workspace/kaggle_verify2/README.md`）。

## ユーザーの定義（2026-11-25 明確化。これが仕様）

- ループ（エンジン）とは、最小盤面 M を維持したまま、そのターン中に、効果と能力の連鎖によって
  アドバンテージが増加する構造。発見は「ループの最小パーツ（エンジン）」と
  「得たリソースから勝利するコンボ（変換）」に分ける。
- エンジンの同一性は増分ベクトルで見る。出力リソースが変われば別エンジンとして扱う
  （実例: サガ単独は {山札−1, 墓地＋1}、サガ＋《死神覇王 XENARCH》は {山札−1, 手札＋1} で、
  後者は手札を単調増加させるループとして機能している）。
- 変換は、資源を恣意的に莫大化した試算ではなく、明示的なループによって実際に増加するリソース、
  効果ストック、無限回使用できる効果・能力を利用するもの。増えたリソースの種類に応じて変換を探す
  （例: 手札を増やすエンジンには、手札を消費・枚数で勝つ変換を当てる）。

## v2 の不備と v3 の差分

| # | v2 の不備 | v3 の対処 |
|---|---|---|
| 1 | 組を一括で判定し、最小性・必要性の検証がないため、寄与ゼロの相方（乗客）が合格した（合格17組中16組がサガ単独と同一増分） | `judge_engine3`: 組全体の合格後、増分ベクトルを「エンジンの同一性」として固定し、「抜く／枚数を減らす」縮小を同一性が保たれる限り繰り返し採用する（貪欲な最小化）。残った最小コアの各カードは、縮小すると同一性が保てないことを確認して必要性を記録する。同一性が変わる縮小（例: XENARCH を抜くと増分が墓地型に戻る）は採用しない＝別エンジンとして扱う |
| 2 | 変換判定が「増えた資源」を身代わり札で人工的に最大化した局面から始まっていた（`judge_conversion` の extra 注入: 墓地＋身代わり10枚、手札＋身代わり4枚、マナ10枚、山札を薄く） | `judge_conversion3`: 認定済みエンジン（最小コア＋変換札1枚）を実際に回す段1（資源評価の探索）で到達した実局面をそのまま引き継ぎ、段2（勝ち狙いの探索）で勝ちを探す。資源の注入はしない。引き継ぎ時点の局面要約（各ゾーン枚数・手札の中身）と、段1で実行された周回を結果に記録する |
| 3 | 変換候補が特殊勝利カタログ固定で、エンジンの出力リソースに連動していなかった | `pair_conversions3`: 候補カードが「使うゾーン」（束の移動元・前提ゾーン・効果が参照するゾーン）を静的にタグ付けし（`conversion_catalog3`）、エンジンの増分ベクトルから決まる型（墓地型／手札型／マナ型／盤面型／山札切れ型／圧力型）と重なる候補を優先する。少なくとも手札型と墓地型は区別される（テストで担保） |

同一ターン性について: 現行の検出（`dmsim/search/game.py` の `record_turn_loops`）は
1ターン分のログ区間（ターン開始時の局面→ターン終了時）ごとに回帰を測るため、記録される周回の
増分は同一ターン内に閉じる。v3 はこれを合格条件として明示し、結果に `within_turn` と
`own_turns`（周回が使われた自分のターン番号）を含める。

解釈上の判断（明示）:
- 最小性は「同一の増分ベクトルが保たれるか」で判定する。抜くと増分が変わるカードは、
  そのエンジンについては必要とみなす（ユーザーの「同一性は増分で見る」に従う）。
- 変換判定で変換札は開始時に1枚だけ手札（特殊勝利クリーチャーは場）に置く。
  これは「変換札を引けている」ことの仮定であり、資源の注入ではない（v2 でも同じ置き方）。
  エンジンの出力リソースそのものは段1の実プレイでのみ増える。
- 段1のターン数（既定2）と周回数は探索の実行に依存する。ただし周回数には増分ベクトルから
  決まる上限（lap_cap、既定12周）が付き、決着前に止めて引き継ぐ（「残課題の解消」参照）。
  「無限回使用できる効果・能力」は、段1で実際に周回が実行され、その到達局面に
  効果ストックや再利用可能な状態が残る形で引き継がれる。

## 残課題の解消（2026-11-25、成果物は ~/workspace/combo3/xenarch3_fixed.json と controls3_fixed.json）

### 修正1: 蓄積段の停止条件（`judge_conversion3` の `delta` / `lap_cap` 引数、`_play_accum`）

仕様（エンジンの増分ベクトルから決まる汎用形。エンジンごとの手書き条件はない）:

- 蓄積量は周回数で数える。開始局面と現在局面の差分 ÷ 増分ベクトルで推定周回数を出し
  （`_laps_estimate`）、上限 `lap_cap`（既定12周）に達したら止める。
- 減るゾーンが「あと2周分」まで減ったら、周回上限より先に止める（枯渇による決着の回避）。
- 結果には「何周で・何ターンで・なぜ止めたか（stop_reason）・切り取りの有無」を記録する
  （各行の `accum`）。

実装上の要点（素直な方法が2つとも失敗したため、この形になった）:

- ターンは探索（play_game＋TurnSearch）に任せる。ただし葉評価は蓄積専用のもの
  （`_accum_value_fn`）に差し替える: 終局した局面は資源量でなく勝敗で評価し（負け＝最低値）、
  増えるゾーンは「開始枚数＋増分×lap_cap」で頭打ちにし、超過周回には減点を付ける。
- それでも行き過ぎたターン（負けで決着／周回上限の超過。ただし勝ちで決着したターンは除く）は、
  そのターンの決定記録（`eng.log`）を開始局面から再生し、停止条件が発火した決定の直後で
  切り取った局面を引き継ぎに使う（`_replay_until`）。再生した局面は実際に選ばれたラインの
  途中経過そのものなので、到達可能性は保たれる。
- 失敗した素直な方法: (1) ターン単位で止める＋価値関数の上限だけでは止まらない。
  探索予算を使い切った残りは貪欲ロールアウトが受け持ち、そちらは価値関数を見ないため
  ループを手で回し続けて自滅する（実測: 証明書で8周ストックした後に約17周を手で回した。
  予算を20000に上げてもターン探索が終わらなかった）。(2) 決定を1つずつ先読み評価で選ぶ
  方式では、探索なら実行できる XENARCH 型のループに入れず、サガ単独のループ
  （墓地型）に流れてしまった。

### 修正2: 仕込みの山札を実カードで構成する（`default_deck_cards`）

仕込み局面の自分の山札30枚＋シールド5枚を、中核の文明に収まる役割補完札
（search/draw/prep/accel/recover、コストの軽い順。basebuild の候補流用）と埋め札で

### 方式

方針（2026-11-25 ユーザー提示）: コンボ発見は ID の静的列挙ではなく、ID を排した
属性表現から求める。静的列挙の発見ランは v2・v3 とも新規エンジン0件だったため、
列挙の拡大ではなく、属性ベクトル空間の近傍（コサイン類似）で既知コアのカードを
置換する「既知コンボの一般化」を候補生成に使う。

- 種: サガ単独 {サガ×2}、サガ＋XENARCH {サガ×2, XENARCH×2}、アカシック最小コア4種
  （アカシック3×1、オルゼキア×2、ウォカンナ×1、ホーリーエンド×1）。
- 除外: 既知コアのカード自身と、v3 発見ランの既知コア集合（KNOWN_CORE 17種＋
  XENARCH＝18種）。加えて種と同名のカード（別セットの同名再録）は「同じカード」
  として除く。同名判定は既知コア18種の名前にも適用する（dmrp12-s01 は
  rules.cards のエイリアスで正規 ID は dm25sp1-003 のため、ID 照合だけでは
  再録を拾えない）。
- 置換パターン（候補129件）:
  - A サガ置換（25件）: サガの近傍カード単独×2。サガの役割を担える別カードがあるか。
  - B XENARCH 置換（40件）: サガ×2＋XENARCH の近傍×2。出力リソースを変える相方の一般化。
  - C サガ相方探索（24件）: サガ×2＋サガの近傍×2（うち1件は B と重複し統合）。
  - D アカシック置換（40件）: 最小コア4種のうち1種をその近傍上位10件に置換（各種10件）。
- 判定: 全候補を judge_engine3（予算1000・シード1）。合格したものは最小コアと
  増分を記録し、（最小コア, 増分）が既知エンジンと一致する場合は変換を再判定せず
  （v3 対照で確立済み）、新規性がある場合のみ judge_conversion3 で変換を見る。
  今回は新規性のある合格が無かったため、変換判定の実施は0件。
- D の後半20件は、1候補で探索が爆発し全体が止まったため、候補ごとに
  420秒のタイムアウトを付けて再実行した（タイムアウトは不合格ではなく未決着）。

- しかしループの相互作用は効果の正確な配線（どの誘発が・どのゾーン移動を・どの
  対象に）に依存し、属性の粗い類似では保存されない。決定的なのは B で、XENARCH の
  近傍40種のうち、サガの出力リソースを墓地から手札に変える相互作用を持つものは
  0種だった。XENARCH 本人の相互作用は、属性が似たカードには無い特異な配線だった。
- サガ自身は近傍の最大類似度が0.723と低く、属性空間でも孤立している
  （A の全滅と符合する）。アカシックは4種の機械仕掛けで、1種の置換では全て壊れた。
- 結論の範囲: 各種の近傍上位10〜40件・予算1000・シード1。属性近傍は候補の「族」の
  絞り込みには使えるが、エンジンの一般化には効果配線レベルの類似（束の移動・誘発
  構造の一致など、より細かい特徴）が要るという示唆が残る。
