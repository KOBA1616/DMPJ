# ノブ自動チューニング（tools/auto_tune.py）
診断→候補（autofix）が「診断が指す1ノブを動かす」のに対し、複数ノブを同時に乱択変異して探す。LLM・課金なし。
- 採用条件: 調整用シード(1..N)で有意に良い → 別シード(1000..)でも有意に良い。再現しなければ `reject_not_reproduced`。
- 評価点: キルの早さが主、盤面・部品の到達の早さを小さく加える（滑らかにするため。Vの足切りではない）。FAIRのみ・holdout除外。
- 採用した設定は `data/autofix/knobs.yaml`（autofix と共通の開始点）。履歴は `--out` の台帳。
- 日次: `python tools/auto_fix.py --targets data/autofix/targets.yaml ... --tune-seconds 1200`（既定0=無効）。
  時間枠は deck_fix(`--deck-fix-budget`)と別枠で加算される。日次全体の枠は自動化スレッドの配分に合わせて `--tune-seconds` を決める。
- 目安: knight_dmc を seeds=10, generations=2, lam=2, workers=4 で約50秒。

## 評価式（部品の重み）の進化 — 2026-11-09 追加
`auto_tune.py` はノブの後、同じ採用条件（調整用シード→別シード再確認）で**部品ごとの重み倍率**（0.25〜4倍）を進化させる。
- 保存先 `data/autofix/parts.yaml`（combo→倍率の並び）。`dmsim.autofix.partsgenome.load_specs_evolved()` が `auto_fix` / `hypothesis_gate` に反映する。
- `--parts-share`（既定0.5）= 世代のうち部品の進化に回す割合。0で無効。履歴は台帳に `parts_mult` で残る。

## LLM なしでどこまでできるか（整理）
| 手法 | 状態 | 機械だけで可能か |
|---|---|---|
| ノブ進化 | 実装済み | 可 |
| 部品の重み進化（評価式） | 実装済み | 可 |
| 失敗分類→候補生成（文法=テンプレート組合せ） | 実装済み(failures.py)。候補の種類を増やすのは文法の追加 | 可（種類は人が足す） |
| 部品の追加・削除、束の発見 | 未 | 可: 失敗局の最終局面で「成功局にあって失敗局に無い札・ゾーン」を統計的に拾い Part 候補にする（次の実装） |
| 評価式の形の進化（遺伝的プログラミング） | 未 | 可だが探索空間が広く過学習しやすい。重み進化の効果が見えてから |
| 経験ログからの価値・方策の学習 | 計画 A/B/C | 可。ただし価値Vは足切りに使わない・公平探索が基準 |
| コードそのものの改造 | 不可（機械では書けない） | 仮説ルーティン＋仮説ゲート（補助） |

## 部品の自動追加・削除 — 2026-11-09 追加
`dmsim/autofix/partdiscovery.py`。勝った局（無ければ盤面到達局、それも無ければ相手の盾を多く割った上位1/3）と、負けた局の**最終局面**を比べる。
- 足す候補: 勝ち側に偏る（ゾーン, 定義ID）で部品表に無いもの。外す候補: 勝ちと結びつかない（差が0以下）ID指定の部品。
- 候補は統計の仮説にすぎない。採否は `evolve`（調整用シード→別シードの再確認）。採用分は `data/autofix/parts_edits.yaml` に保存し、`load_specs_evolved` が反映する（部品表の長さが変わるので重み倍率は作り直す）。
- `auto_tune.py --discover-gens`（既定2、0で無効）。注意: 勝ちがほぼ出ない対象は代用指標（相手の盾）で作るため、ビート寄りの候補が出やすい。採否の指標がキル・盤面・部品の到達なので、効かない候補はここで落ちる。
