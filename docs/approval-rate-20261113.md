# カード承認率の集計と上げ方（2026-11-13）

集計: `python tools/approval_stats.py`（読むだけ。台帳は data/cards/approvals、無ければ origin/cards-data から読む）

## 1. 現状（対象 = サイキック・GR を除く 23,122 枚、名前の異なりは 11,799）

| 段階 | 枚数 | 割合 |
|---|---|---|
| 変換済み（main の converted.yaml ほか） | 9,700 | 41.9% |
| 定義の検査 parse_card 通過 | 9,700 | 41.9% |
| 承認済み（今のコードで有効） | **1** | 0.0% |

### 承認とは（コード）
- `dmsim/cards/approval.py` の `is_usable`。台帳 `data/cards/approvals/<弾>.json` の `status: approved` で、`stale_reason` が無い（`def_hash` が今の定義と一致、`vocab_ver` が使う op・キーワードの今の定義と一致、`verifier` が最新）こと。または カードファイル側の `source.review: approved`（開発者モードで人が付ける）。
- 台帳の `by`: `rule`（ルール変換の札が verify_card＝実対局で回る＋effectcheck の text/effect 検査を通過）、`check`（LLM 変換の札で effect: ok まで確認できたもの）、`human`。付けるのは `tools/auto_approve.py`（Actions の auto-approve.yml、6時間ごと、cards-data ブランチ上）。
- 語彙や定義が変わると承認は自動で pending に戻る（再検査で自動承認に戻せる設計）。

### 「1枚だけ」は読み違いか → 半分は読み違い、半分は本当
- 台帳は **main に無く cards-data ブランチにだけある**。main で `load_rules(only_approved=True)` を呼ぶと台帳が空なので、ファイル上で人が承認したオルゼキア1枚になる。
- cards-data の台帳には 1,629 件あり、うち 1,613 件が自動承認済み（rule 1,593・check 20）。
- ただし今の main のコードで照合すると **1,544 件は「語彙の定義が変わった」、69 件は「定義が変わった」で無効**。auto-approve は Actions 無料枠切れで 11/10 から止まっており、再検査されていない。
- 試しに手元で auto_approve を 40 枚だけ再実行したところ **40/40 が再承認**（1枚あたり約1秒）。止まっている自動承認を回せば 1,600 枚前後はすぐ戻る見込み。

LLM 変換の札（約8割）は effect: ok が出ないと自動承認されない（skipped_not_rule）。8,075 枚のうちどれだけ通るかは未測定。

## 3. 上げ方の案

### 案A: 今の基準のまま自動承認を回し直す（基準は変えない）
- 中身: auto_approve を手元/PC のワーカーで回す（Actions 不要、無料）。台帳を cards-data から main 側でも読めるようにする（集計スクリプトは対応済み）。
- 人手: ほぼ0。誤承認の危険: 今と同じ。
- 見込み: 1,600 枚前後は確実。8,075 枚のうちルール変換分＋effect: ok の LLM 分が上乗せ（推定で 15〜30%台まで）。90% には届かない。

### 案B: 段階つき承認（基準の追加。要判断）
- 段1「機械照合済み」: verify_card＋text/effect 検査＋**公式テキストとの往復照合**（効果データ→文を再生成し原文と一致度を見る、無料モデルかルール）。
- 段2「型でまとめ確認済み」: 同じ効果の形（op の並び＋値の型）ごとに代表2〜3枚を人が見て、同型の札をまとめて承認。形の数は数百程度の見込みなので、人手は数時間〜1日×数回。
- 段3「人が1枚確認」: コンボ発見で使う札だけ。
- 誤承認の危険: 段2は「形は同じだが数値や対象が違う」札で起きうる → 往復照合で数値・対象の一致を必須にして抑える。コンボの登録には段3を必須にする。

### 案C: 使う札から優先（案A・Bと組み合わせ）
- 優先順: ①登録簿の中核（アカシック3、オルゼキア、ホーリーエンド、ウォカンナ、サガ、シャコガイル、ドラゲリオン など7〜8枚）→ ②data/decks の札（基盤選びの札を含め実カード136枚、今の有効承認は1枚、台帳上の承認28・pending 3・台帳なし104）→ ③対局ログに出た札 → ④残り。
- 人手: ①②で150枚前後、1枚数分で半日〜1日。

### 90% について
- 未変換 10,521 と語彙不足 2,899 があるので、どの案でも変換が先に進まないと 90% は出ない。分母を「名前の異なり」（11,799）にすると再録の重複が消えて作業がほぼ半分になる。

## 4. 決めてもらう点
1. 段階つき承認（案B）を入れるか: 入れる（推奨。コンボ登録は段3必須）／入れない（今の基準のまま）。
2. 90% の分母: 名前の異なりで数える（推奨）／ID（再録込み）で数える。
3. 自動承認をどこで回すか: koba の PC のワーカーに auto_approve を積む（推奨、無料）／12/1 の Actions 再開まで待つ。
4. 中核・デッキの札 約150枚の人の確認: 開発者モードで koba が見る（推奨、半日〜1日）／見ない。
