# システム構造の見直し: 統合修正プランとドキュメント計画

2026-11-16 の「システム構造の見直し」依頼と Gemini 対話の検討を統合した
全体計画。各論の詳細は個別ドキュメントに置き、ここは地図と状態の一覧に徹する。
方針の前提: **システム完成を最優先**。当面の優先は「公式テキストから動く
シミュレーション環境」で、代表検証は絶望神サガループ。

## 1. 見直しで確定した原則

- **責務分担**: 「どの未来が有望か」は大局観（MacroPlanner の段階目標の鎖への
  充足率）。V はターン内の葉評価専用。順序関数はターン境界の保持の実行側に
  徹し、除外ではなく優先付け専用。詳細は order-function-generalization-plan.md。
- **主張の規律**: キルは再生検証済みの記録がある時のみ。勝ちなしは最終段
  または横断探索の打ち切りなし完走時のみ（途中段・貪欲確定の非発見は
  unknown）。最速の主張には前ターンの完全列挙と保持の完全性が要る。
- **保持の階層**: 既定は全保持（証明の金標準）。削る必要が出たら優先付けで
  削り、削った事実を capped として記録する。beam は実運用の標準スキャン。
- **再現性**: 保持選択は順序非依存（全順序＝スコア列＋局面キー）。設定は
  ハッシュで記録名に埋め込み、エンジン版（git describe）で再開条件を照合する。
