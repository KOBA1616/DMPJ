# サガで探索がループを選ばない原因（2026-11-13 調査）

対象: 陽性対照（`dmsim/eval/ruler_control.py`、PR #407）でサガの段2到達率が 0.12 だった件と、通常開幕（FAIR、PR #408 `dmsim/eval/assemble.py`）でサガの入口へ向かわない件。コードの挙動は変えていない。診断は `tools/diag_loop_miss.py`（検出器と verify の成否を数えるだけ）。

## 結論

1. **ループ証明書が一度も成立していない（失敗の 100% の根）。** サガの入口局面では、ターン探索 `TurnSearch` のループ検出（`Detectors` → `verify` → `_stocks` で周回をまとめて進める仕組み）が、どのシードでもサガの蘇生ループを証明書にできていない。勝てた局面も、約55〜70手（サガの蘇生 9〜14 回）を深さ優先で**総当たりに掘り切って**勝っているだけ。
2. **だから予算で決まる。** 総当たりで掘り切れるかは手札の枚数・種類（捨てる札の選択肢）と候補の並び順しだい。元の入口局面（seed 0）はたまたま 200 ノードで届く並びだった。手札が変わると 200 では届かず、届かない葉は殴りの準備が高く付くので、2ターン目に殴り勝ちを選ぶ。
3. **通常開幕で入口へ向かわないのは別の原因。** シャコガイルはコスト9で、saga_entry デッキには踏み倒し・軽減の札がない（サガが出せるのはコスト5以下のゴッド・オリジン）。自分の6ターン目までにマナ9は届かないので、葉の評価以前に**入口への道（Route）がデッキにない**。S5（デッキ構築）側の問題で、探索の直しでは治らない。
4. **アカシックが予算 200 で 0 なのも 1. と同じ形。** 1周目が長く、200 ノードでは検出器が同じ骨格への戻りを一度も観測しない（成立 0 件）。1500 では観測され、verify も通って山札切れ勝ちになる。

### 原因ごとの内訳（失敗 12/12 シード、b200）

| 原因 | 当てはまる割合 | 根拠 |
|---|---|---|
| ループの最初の手が候補にない | 0/12 | サガを出す手はどのシードでも main の候補に入る（勝ち手順の2手目が `play:dm22ex2-021`） |
| 枝刈り（`seen` の同一局面）で落ちる | 0/12（主因でない） | 予算を上げれば同じ探索で勝ちに届く |
| **ループ検出が成立しない** | **12/12** | 検出器の成立はサガ 13 シード中 seed 3 の 3 件だけ、verify は全部失敗。証明書による周回の早送りは一度も起きていない |
| **予算切れ（総当たりの深さ 55〜70 手に届かない）** | **12/12**（上の帰結） | 予算を増やすと勝ち率が単調に上がる |
| 葉の評価で負ける | 二次的 | 届かない葉どうしの比較で、ループを途中まで回した葉は自分の山札が少なく `deck_danger`（山札 8 枚未満で 1 枚 60 点減点）で大きく減点され、殴りの準備の葉に負ける。ループの手を「見つけたのに捨てる」ケースはない |

### なぜ証明書が成立しないか（コードで確認）

サガの1周は「サガが出る → 1枚引く → 1枚捨てる → 墓地のサガを出す → 自分を破壊」。カウンタの差分は `deck:0 -1, graveyard:0 +1` で、`is_burn`（山札だけ減る）に当たる。ところが:

- 山札削りを受け付ける検出器（`burn_loops=True`）は手札の中身を骨格に入れる（`hand_keys=None`）。引いた札と違う札を捨てると手札が変わり、骨格が戻らない。引いた札そのものを捨てた周だけが一致する。
- 手札をぼかす検出器（`hand_keys=draw_keys`）は資源ループ（手札・マナが増える）しか受け付けない。サガの1周は手札が増えないので `is_engine` でも `is_burn` 扱いでもなく、捨てられる。
- 成立しても `verify` は前の周の選択の意味キー（`hand:dmrp03-036:0` のように「どの札を捨てたか」）をそのまま再生するので、次の周に引いた札が違うと `diverged` で落ちる（seed 3 の 3 件はこれ）。
- 実際の勝ち手順は、途中でイザナギテラス（山札の上5枚から1枚）、イワシン（墓地に置かれたら引いて捨てる）、E・タイフーンなども混ざり、毎周同じ行動列ではない。

つまり**「引いて捨てる」型のループ（引く札が毎回違う）を証明書にする手段がない**。サガ専用の問題ではなく、ドロー・ディスカードを含むループ全般に当てはまる。

## 2. アカシック（標準予算 200 で 0）

`tools/diag_loop_miss.py akashic 200` / `1500`（seed 0〜4）:

- b200: 検出器の成立 0 件。1周目を終えて同じ骨格に戻る前に予算が尽きる。
- b1500: 成立 1〜3 件、うち verify 成功 2 件（失敗はアカシック3 `play:dmrp12-s01:1` の意味キーずれ）。成功した証明書で周回を早送りし、山札切れ勝ち。

原因は「1周目が長い（分岐が多い）ので、深さ優先の予算 200 では1周目を回り切れない」。証明書の仕組み自体はアカシックでは働く。

## 3. 通常開幕（FAIR）で入口へ向かわない件

PR #408 の実測（中核が揃った 14 局すべてでシャコガイルが場に出ない）について:

- シャコガイル（コスト9）を場に出す手段が saga_entry デッキにない。デッキの札（上の表の札とアクア・ナイト、ミラージュ・マーメイド等）にコスト軽減・踏み倒しはなく、サガが墓地から出せるのはコスト5以下。マナチャージ1枚/ターンとコダマダンス・チャージャーで6ターン目のマナは最大 7〜8 前後。
- よって「葉の評価がシャコガイルを場に出すことを評価していない」は主因ではない（出せる局面が来ない）。入口 M（シャコガイルが場）へ届く Route がデッキにないので、S5（デッキ構築）の課題。入口局面の注記「シャコガイルは前のターンまでに場に出ている」は、通常開幕からは再現できない仮定と明記すべき。
- 入口局面の見落とし（§1）とは**別の原因**。共通点は「探索が多ターンの計画を持たない」ことだけで、直し方も別。

### FAIR でループを記録するのに要るもの

`FairTurnSearch` は決定化ごとの `TurnSearch` に**最初の1手の投票**をさせるだけで、各探索の `stats.loops` / `stats.chosen` を捨てている。`fair_game` は `lock_judge` も呼ばない（`dmsim/search/game.py` 144 行の説明どおり）。段1を FAIR で測るには:

1. 真の局面で実際に指した手順（ターンの `eng.log`）に `find_pattern_loops`（有限ループの事後検出、`dmsim/search/pattern_loop.py`）をかけ、`GameResult.loops` に積む。真の手順だけを見るので公平性を壊さない。いちばん小さく効く。
2. 証明書は真の局面で `verify` し直して採る（決定化した山札で作った証明書は、真の山札では引く札が違うので、そのままは使えない）。§4 の案 A（引いて捨てる型の一般化）とセットで意味が出る。
3. `fair_game` にも `play_game` と同じく `lock_judge` を渡せるようにする（ロック判定は真の局面の写しで回すので、観測の公平さとは独立）。

## 4. 直し方の案（推薦順）

| 案 | 中身 | 効果の見込み | 副作用・注意 |
|---|---|---|---|
| **A. 引いて捨てる型のループを証明書にする**（推薦） | (1) 手札をぼかす検出器でも `is_burn` の差分を受け付ける。(2) 証明書の行動列で、手札の札を選ぶ決定を「骨格に入らない札（hand_keys 外）のどれか」という抽象キーで記録し、`verify` / `fast_forward` ではその抽象キーを満たす札を規則的に選ぶ（例: 直前に引いた札、なければ hand_keys 外で最小の札）。(3) ストックの周回数は山札の残り（上限 `limit`）と勝ち条件で決める（今の `burn_stock` と同じ） | サガ入口は数周で証明書が成立し、早送りで山札の最後の1枚まで進むので、予算 200 でもほぼ全シードで届く見込み（要実測）。未知のコンボでも、ドロー・ディスカードを含むループ全般に効く | 抽象キーの選び方で「捨ててはいけない札（勝ち手段）を捨てる」ことがある → hand_keys に入れる札（入口時点の手札）は捨て先にしない規則で防ぐ。`verify` の厳密さが下がるので、早送りの後に骨格と差分を確かめ直す（今の verify と同じ検査）。同一シード同値性は変わる（探索の挙動が変わるため。日次の数字が動く） |
| B. 葉の評価の `deck_danger` を「山札切れが負けにならない札が場にある」とき外す | シャコガイルのような置換（「負けるかわりに勝つ」）や、山札を戻す能力を見て減点を止める。一般的には「自分の山札切れで負けない」を `goal_distance` と同じくカードの能力から読む | 予算切れ時の打ち切り葉でループ途中の線が殴りに負けにくくなる。単独では総当たりの深さは変わらないので効果は小さい（A の補助） | 置換の読み取りを誤ると本当に山札切れで負ける線を選ぶ。lock 系（自分の山札切れ対策）と干渉しないか確認が要る |
| C. 予算配分: 反復深化か、ルートの子ごとの予算の等分 | 深さ優先で最初の子に予算を使い切らないように、各候補に最低予算を配る | アカシック（1周目が長い）とサガの両方に一般的に効くが、伸びは数倍の予算増と同程度 | 同じ予算で浅い線が増えるので、殴りの線の質が落ちる可能性。速度は変わらない |
| D. 登録簿の既知ループ（LoopSpec）を「勝ちプラン」として探索に渡す（P3「プレイで使う」） | 入口 M を満たしたら、その LoopSpec の Route／ループの手を優先展開し、予算を予約する | 既知コンボには確実に効く（入口局面の陽性対照は合格しやすくなる） | 既知コンボにしか効かず、陽性対照が「探索の力」ではなく「登録簿の力」を測るようになる。未知コンボの発見には効かないので、A の代わりにはならない。陽性対照では使わない設定で測るべき |
| E. 優先展開（ループの入口の手を先に試す） | 自分の墓地・場に戻る札（蘇生・回収）を出す手を候補の先頭に | 安いが、どれが入口の手かを一般に当てる規則がなく、効果は局面次第 | 他のデッキで殴りの手順付けを悪くするおそれ |

推薦: **A を先に入れて陽性対照で測り、次に FAIR のループ記録（§3 の 1・3）、足りなければ C**。B は A の後に効き目を見て判断。D は P3 で入れるが、陽性対照（物差しの校正）では外して測る。通常開幕でシャコガイルに届かない件は探索ではなく S5（デッキの Route）として別に扱う。

### 実装タスクへの分割案

1. **A-1** 検出器: 手札をぼかす検出器で burn を受け付け、手札選択の抽象キーを証明書に記録する（`dmsim/engine/loop.py` の `LoopDetector` / `LoopCertificate`、`search/turn.py` の `Detectors`）。単体テストはサガ入口 seed 1〜12 の小局面。
2. **A-2** 再生: `verify` / `fast_forward` が抽象キーを解決する。捨て先の規則と、早送り後の再確認。サガ・アカシックの陽性対照と、日次の同一シード比較（数字が動くことを報告）。
3. **F** FAIR のループ記録: `fair_game` で真の手順に `find_pattern_loops` をかけて `loops` に積む、`lock_judge` を受け付ける。段1を FAIR で測る経路を作る。
4. **C**（必要なら）予算配分: ルートの子ごとの最低予算か反復深化。アカシック budget 200 で測る。
5. **S5 側の記録**: saga_entry デッキに入口へ届く Route がないことを、物差しの設計書（揃うの目盛り）の注記に足す。

どの案でもシャコガイルの着地と入口は 0。分かれる手（saga_doom_d seed 23 の手順で確認）:
1. **シャコガイルが墓地にない。** 探索は手札のシャコガイル（コスト9）をマナに置く。ドラゲリオンを出した時、シャコガイルはマナと盾にあり、進化元にも墓地にもなかった。メテオバーンで下から墓地に置いたのはイワシン（引いて捨てる）。
2. **ドラゲリオンを出せる状態でも出さない / 出すのは勝つターン。** 出せる状態になった局の多くで探索は別の手を選び、出した4局はどれも同じターンに殴りで勝った。相手が無抵抗なので、その時点で最も高い葉は殴りの準備になる。

デッキ構築（dmsim/deckplan）は、候補札の分類（pool.classify の prep=墓地肥やし）は使えるが、採否の点数（eval.deckeval.harness_scorer）がキル率なので、殴り勝ちで飽和して（24局中21〜24局勝ち）経路の差を見分けられない。今回は分類で墓地肥やしの候補を出し、案は手で組んで経路の到達で比べた。経路を点数にするには、到達の述語（入口・シャコガイル着地）を scorer に渡せるようにする必要がある。

## 8. 経路の段を探索の目標にする（P3 先行実験、2026-11-13 追記）

- 既存の部品: 段階目標 reach_chain は山札を見る探索専用（play_api の chain、FAIR 未実装）。大局観 plan_w は点数加算で有意な効果がなく標準外（V の特徴量側）。公平探索に目標を渡せる口は葉の評価 `value_fn` だけなので、leaf_parts と同じ形で作った（TurnSearch の候補・払い方には触れていない）。
- データ: `data/loops/route/<名前>.yaml` の `stages`。段 = 述語の組（入口 minimal と同じ形: zone|zones, match{name|types|civs|races}, n, op, owner）か `entry: <入口名>`。局面の点 = 満たしている最も後ろの段までの weight の合計（後の段が前の段の状態を消してよい）。読み手は `dmsim/search/route_goal.py`（load / reached / make_value_fn）。登録簿から読む時はこの YAML をそのまま持てばよい。
- 切り替え: `assemble.run_one(route=名前)` で目標あり、`route_log=名前` で段の到達だけ記録（行の `stage_turn`）。既定はどちらも None で従来どおり（main と同じシードで一致を確認）。
