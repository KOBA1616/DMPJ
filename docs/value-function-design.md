# 評価関数 V の設計（2026-11-10 koba と合意）

状態: **設計のみ・未実装**。現状との差は §6。決定の経緯はプロジェクトチャット（内部AIのスレッド）。

## 1. 目的
3〜4ターンキルを目的に、探索の**順位づけ**を助ける。足切り（局面を捨てる判断）には使わない。公平探索（相手の山札・盾の中身を見ない）の情報だけを使う。

## 2. 入出力
- 入力: 局面の特徴量 + **計画**（大局観システムから）。
- 出力（別々のヘッド。1つの数に混ぜない）:
  1. **T内勝率** V(局面, 計画) = その局面から、その計画に沿って打ったとき T ターン以内に勝つ確率（T=3,4,…）。
  2. **再現性確率** = 同じ計画が別の山札順・先後・相手でも成立する確率（決定化した多数の山札順での成功率の分散・下限で測る）。
  3. **コスト対総合パフォーマンス** = §4。
  - 補助出力: 小目標の鎖の各段への到達確率（勝ちが出ない対象でも学習できる）。

## 3. 特徴量
- 盤面（静）: 自分の場・手札・マナ・墓地、相手の盾・山札の枚数など。
- リソース（静）: 手札・マナ・盾の枚数、**盾の束**（盾の下の合計枚数・最大の束・束のある盾の数）、部品の所持。
- 効果スタック: 待機中の効果、S・トリガーで出うる札、ブレイクで起動する効果、**場で有効な継続効果（ロック類）**と、それが相手の「できること」を減らした量。
- 期待状態: 計画が成功したときの次の状態（小目標の次の段）と、現在との差（あと何段か）。

## 4. コスト対総合パフォーマンス
- 分母: 使用マナ（マナ0の手は、手札・場の札の消費をマナ換算で加える。重みは小さく始める）。
- 分子: 起きた現象の種類別の和（内訳ベクトルと重み付き合計の両方を残す）。
  - リソース増減（手札・盾・盾の下・マナ・墓地）
  - 盤面強化（場の数・パワー・ブレイク数・ブロッカー）
  - 妨害・除去（相手の資源・クリーチャー・盾の破壊）
  - ロック: 行動の制限（プレイ・攻撃・ブロックの制限）、起動の妨害（能力の無効化・誘発の抑止）、無効（打ち消し・置換）、資源の枯渇（マナ全破壊・山札切れへ向かう）
- ロックの測り方: 相手の合法手の数と、相手が実際に使えるカードの数の、前後の差。
- **場にいる間続く効果**（常在型の静的能力）は一度きりでなく、「場にいるターン数 × 減らした「できること」」を累積する。離れれば消える。除去されやすさは相手モデルが簡易なため未対応。
- 重みは、最初は人が決めた小さな表。後で、既知コンボの再発見に必要な探索量が減るよう進化的に調整する。

## 5. 計画（大局観との連携）
- 連携は API でなく**直接（同一プロセス）**。V は探索で局面ごとに何万回も呼ばれ、遅れを増やさないため。
- 計画の形は版つきのデータ `Plan`（狙い intent、目標部品、小目標の鎖と現在の段、予算）に固定する。MacroPlanner（規則ベース v1、docs/loop-discovery.md）、将来の学習版、逆算の展開器（notes/combo-loop-discovery-design-20261110.md 手順3）のどれが出しても同じ形で渡せる。Rust 化の境界にもなる。
- 学習データは (局面, 計画, 結果) の組。

## 6. 現状（実装済みのもの）との差
- 手で決めた `evaluate`（dmsim/solitaire.py）と `priority`（dmsim/discovery/bestfirst.py）: 静的な盤面と枚数の重み和 + 待機中の効果数 + 自盾の枚数（ゴール札があるときのみ）。局面が変わるたび候補ごとに計算する。収支・継続効果・束・計画の項はない。
- 学習した V（dmsim/autofix/valuelearn.py）: 線形リッジ回帰。特徴は枚数と部品の所持のみ。ラベルは -(キルターン)。順位づけの加点（learned_mult、初期 0）。日次の調整で再学習。勝ちが出ない対象ではラベルがほぼ一定で学べない。

## 7. 採否の基準と注意
- 新しい V を入れたとき、既知コンボ（天門など）の**段階到達率**が手で決めた評価と同じか上がること。下がるなら採用しない。
- 測定器・効果データが変わったら、古い学習データは無効にして学び直す。
- 探索の長さ（ターン上限）で結果が大きく変わる（天門: 8ターン上限では 0/8、14ターンで 8/8）。測定ではターン上限を明記・固定する。
- 保留: 相手モデルを `charge_only` から実際にカードを使う簡易方策へ変える（ロックの実害を測るのに必要）。
