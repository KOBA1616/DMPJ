# ループ列挙（設計メモ 手順1〜2）の最初の結果（2026-11-10）

`tools/loop_enum.py`: 資源の流れ網（zone_graph）の長さ1〜3の閉路を数え、式（1周で自分の資源が減らない・山札だけは削れてよい・sure）で絞り、cyclesetup の局面でエンジン再生（res.loops）して確かめる。

| 項目 | 結果 |
|---|---|
| 全閉路（束の長さ1〜2、全札） | 789,299 |
| 式OK | 29,859（3.8%） |
| 陰性対照: 式OKから40個を再生 | エンジンがループと認めたもの 0 / ロック 0 |
| 既知コンボの中核だけの網（式OK / 再生で検出） | 天門 0/0、サガ 11/0、騎士 0/0、アカシック 3/0、ドリル 0/0 |

読み取り: 既知のループは再発見できていません。原因は、既知ループが長さ1〜3の閉路ではなく、複数の札が各自を複数回使って資源の収支が合う（設計メモの C·x ≥ 0 の x が 1 より大きい）形だからです。閉路だけを数える方式では足りず、遷移ごとの使用回数を求める整数計画（または増分の合計つきの閉路列挙）が必要です。また、再生で0なのは、cyclesetup の仕込みが「ループが回り始める局面」ではないためと、式の偽陽性の両方が考えられます（どちらかは未切り分け）。

## 追記: 有限ループと時計の扱い（同日）
- 有限ループ: 1周で減る資源（自分のマナなど）は「在庫÷消費」周まで回せるとして、相手側の効果×周数を価値にする（`lap_bound`）。
- 時計（ターン終了など）が前提の束は、時間が進めば起きるものとして、どの束からも受け渡し可能（sure=False＝時間頼み）にした（`cycles_among`）。
- 結果: ドリル・スコール＋天雷王機ジョバンニが、「周数6・相手マナ6枚を墓地へ」の有限ループとして静的に出た。アカシックは1つ（周数3）。サガ・騎士・天門は相手に効く閉路は出ない（別の勝ち筋の形）。
- 注意: ドリルは holdout だが、この時計の扱いを決める診断で見てしまったので、もう純粋な holdout ではない。ランダム3枚の組で「3周以上・相手に効く」閉路を持つ割合は 6.3%（基準率）。
